DSH Sidebar は公式 DeepSeek Harness ランタイムを VS Code に統合します。プロジェクト別の会話、独立したサブエージェント詳細、明示的なファイル参照、ネイティブの差分レビューを提供します。

現在のソースバージョンは **0.1.23** です。変更履歴は [CHANGELOG.md](CHANGELOG.md) を参照してください。元の拡張機能は [Lixxx1](https://github.com/Lixxx1) が作成しました。

## ✨ 特長

- **会話と履歴。** 公式 DSH ランタイムで応答を受信し、ツール呼び出し、承認、質問、過去のメッセージを確認できます。
- **失敗した応答の復元。** リクエストが失敗しても受信済みの内容を保持し、会話とサブエージェント詳細にエラーコードと理由を表示します。保存済みの失敗した試行は履歴を開き直しても復元されます。再試行は個別に保持し、保存できなかった出力は現在の画面内でのみ利用できることを明示します。
- **会話ディレクトリ。** 最近の会話とアーカイブを検索、名前変更、アーカイブ、復元できます。新規会話は通常の会話画面を開き、モデル、推論強度、エージェント構成、権限を選択できます。アーカイブ直後は Undo を利用できます。上部の一覧はメイン会話を切り替えます。
- **独立したサブエージェント詳細。** Tasks から子タスクを開き、メイン会話の隣で状態、履歴、ツール出力、実行時間、トークン数を確認できます。承認、質問への回答、停止に対応し、親エージェントが許可する場合は Queue／Steer を送信できます。単発タスクの入力欄は読み取り専用です。外部実行は情報行として表示し、ローカル会話として開きません。
- **バックグラウンドタスクとサービス。** 長さを制限したプロセス出力、Goal の状態とラウンド上限、Schedule の通知と配信履歴、Workflow の段階とジョブログを表示します。利用可否はランタイムのサービスによります。履歴検索を有効にすると本文を検索できます。
- **明示的なファイル参照。** `+` からファイルやフォルダーを追加し、`×` で個別に削除できます。`@` と **Add Selection to Chat** にも対応します。現在のファイルと選択範囲は任意の候補です。リソースのドロップと画像の貼り付けにも対応します。
- **会話設定とキュー。** エージェント構成、Permission、Plan、Model、Reasoning Effort を選択します。追加メッセージのキュー、実行中タスクへの Steer、保留中コマンドの確認と削除に対応します。
- **コンパクトな差分レビュー。** ファイル数と追加・削除行数を折りたたんで表示し、展開または Review から VS Code Diff Editor を開きます。Keep／Revert はターン別のスナップショットを使用し、元の会話とプロジェクトを検証します。取り消しの確認後にも対象を再検証します。
- **DeepSeek 認証。** API キーまたはブラウザー経由のログインを使用し、状態と残高を確認してログアウトできます。リモートログインは VS Code のポート転送を使用します。
- **プラグインと設定。** Tools、Skills、MCP、Memory、Agent Hooks を管理します。歯車から専用設定画面を開き、モデル提供者、Shell、Agent loop、サブエージェント、Web 検索、一般設定を編集できます。
- **ランタイムの復旧。** 管理対象ランタイムのウィンドウ間共有、再接続、会話の占有診断、識別済みの残存管理プロセスの終了に対応します。保存した外部ランタイムには接続のみを行います。
- **デバッグとキーボード操作。** `.vscode/launch.json` の自律デバッグでブレークポイント、ステップ実行、スタック、変数を操作できます。`Cmd/Ctrl+Alt+D` は会話を開き、`Cmd/Ctrl+Alt+L` は選択範囲を追加し、`Cmd/Ctrl+Alt+F` はファイル修正を要求します。会話とタスク詳細はダーク、ライト、高コントラストに対応します。

## 📦 インストール

まず公式の DeepSeek Harness CLI をインストールします:

```sh
npm install -g @deepseek-ai/dsh
```

DSH は拡張機能を実行するホストにインストールしてください。Remote SSH ではリモートホストです。

### 公開リリース版

[GitHub Releases](https://github.com/fallleaves01/dsh-vscode/releases) から対象バージョンの `.vsix` をダウンロードし、VS Code の **Extensions: Install from VSIX...** で選択してください。この fork の拡張 ID は `fallleaves01.dsh-sidebar` です。

公開済みのファイルは `main` より古い場合があります。必要なバージョンが未添付の場合は以下の手順でビルドしてください。上流の Marketplace 拡張機能は独自の発行者とリリース日程を使用します。

### 最新の開発ビルド

`package.json` で指定した pnpm バージョンで現在のソースをビルドします:

```sh
git clone https://github.com/fallleaves01/dsh-vscode.git
cd dsh-vscode
pnpm install --frozen-lockfile
pnpm run package
```

**Extensions: Install from VSIX...** を実行し、生成された `dsh-vscode.vsix` を選択してください。ソースビルドを更新するには変更を取得して再ビルドします。インストール済みのバージョンは拡張機能ビューで確認できます。

VS Code 1.100 以降と Node.js `^22.19.0` または `>=24.0.0` が必要です。

コミュニティ製のランタイムプラグインをインストールする場合は、`pnpm` が PATH に通っている必要があります。

## 🚀 使い方

1. 信頼済みのプロジェクトフォルダを VS Code で開きます。
2. 右サイドバーで **DeepSeek** を選択します。表示されていない場合は **その他のビュー** から探してください。
3. 鍵ボタンから `DEEPSEEK_API_KEY` を設定するか、**DeepSeek Harness: Sign In to DeepSeek Account** を実行します。
4. 新規会話で通常の会話画面を開き、モデルと推論強度、ファイル参照を選んで送信します。会話設定メニューで Permission とエージェント構成を選択します。`/plan` で Plan モードに入り、`/` で DSH コマンドを開きます。
5. Tasks からサブエージェント詳細を開き、変更概要から差分を確認します。ディレクトリでは検索、名前変更、アーカイブ、復元を行えます。
6. 歯車または **DeepSeek Harness: Open Settings** からランタイム設定を開きます。プラグイン管理からも同じ画面を開けます。

サブエージェントのツールカード内で名前を選択すると、その子会話へ移動します。右端の矢印は独立した詳細ペインを開きます。元の要求と結果は折りたたんで確認できます。

### 任意のタスクサービス

**DeepSeek Harness: Configure Task Services** から `enableHistorySearch` と `enableSchedule` を設定します。標準の管理対象 Web ランタイムで本文検索と Schedule を有効にします。反映には再起動が必要です。カスタムまたは外部ランタイムでは、そのプロファイルで対応サービスを提供する必要があります。

### 複数ウィンドウの共有ランタイム

同じホスト・OS アカウント・`DSH_HOME` と互換性のある起動設定では、
`reuseAcrossWindows` により一つの DSH を共有します。履歴検索と Schedule も維持します。
起動したウィンドウを閉じても他のウィンドウは継続でき、最後の正常終了で DSH を停止します。
全拡張ホストが異常終了した場合、補助プロセスは生存記録を確認し、30 秒の猶予後に終了処理します。
5 秒ごとに確認し、DSH の自動再起動や出力ログ保存は行いません。接続失敗や設定の不一致は
別プロセスを起動せずに通知します。Restart Runtime は設定不一致で接続できない場合でも、
記録済みの管理対象ランタイムを現在の設定で置き換えます。他のウィンドウが使用中なら、
実行中の会話・サブエージェント・定期処理への影響を確認してから再起動します。
キャンセル時は現在の接続を維持します。停止前に対象プロセスと利用者を再確認し、
旧プロセスの終了後に起動します。外部ランタイムは停止しません。
そのウィンドウだけの接続回復には Reconnect を使用します。共有時はウィンドウに結び付く
autonomous debugging を無効にしてください。0.1.15 より前から更新する場合は作業を完了し、
全利用ウィンドウを更新して Restart Runtime で旧補助プロセスを置き換えてください。
0.1.16 は更新後のウィンドウを再読み込みすると、互換性のある 0.1.15 補助プロセスを再利用できます。

既存の管理対象インスタンスへの接続はツールバーの **Shared** で示し、ツールチップに PID を表示します。
クリックすると現在のウィンドウを再接続します。読み込み中は接続・イベント購読・履歴読み込みの段階と
**Show Output** を表示します。`autoStart` が無効なら Starting ではなく **Connect** を表示し、
接続失敗後も **Retry Connection** で既存インスタンスの検出を再試行できます。

Linux Remote–SSH では各ウィンドウの利用記録と操作を VS Code Server のプロセス識別情報に
結び付けます。Server 終了後に残った拡張ホストは DSH を保持できません。予期しない切断の
猶予はローカルユーザー設定の `remote.SSH.reconnectionGraceTime`（秒）に従います。
変更の反映には遠隔 Server の再起動が必要です。正常なウィンドウ終了は即時停止になる場合があります。
応答しない DSH は SIGTERM の 4 秒後に強制終了し、出力パイプの無期限待機を防ぎます。
補助プロセスが強制終了しても、接続中のウィンドウが残っていれば識別済み DSH を終了処理できます。
DSH 本体やユーザー設定は変更しません。補助プロセスと全拡張ホストが同時に終了した場合、
次回の管理対象接続で会話を開く前に登録情報を確認します。正常な補助プロセスが残っていれば再接続し、
補助プロセスが終了し有効な利用者がいなければ、識別済みの残存 DSH を終了して一つの代替インスタンスを起動します。
複数ウィンドウの回復は直列化します。新しい補助プロセスは URL 公開前にも DSH の起動識別情報を記録します。
保存済み履歴は再開できますが、中断したモデル要求やツール実行はそのまま継続できません。
識別情報の記録前の強制終了、カーネル I/O 停止、信号の拒否などは自動終了処理を妨げます。
不確実な記録は保持し、競合するインスタンスは起動しません。
詳細は [英語 README](README.md#shared-runtime-across-windows) を参照してください。

### DSH 設定

歯車は会話内の設定ダイアログを開きます。公式のアイコン、ナビゲーション、カード寸法を使用し、
狭いサイドバーではアイコンレールに切り替えます。**DeepSeek Harness: Open Settings** は同じ画面をエディタータブで開き、公式 DSH の設定項目を編集
します。提供者の端点・モデル一覧、Shell のタイムアウトと出力上限、並列ツール数、
サブエージェントの深さ・容量・許可モデル、Web 検索、アカウント状態とログ送信に
対応します。Messages API と Search / Fetch API の切り替え、個別の端点・制限値・資格情報、
カスタム Pi 提供者の推論レベルと API 値の編集にも対応します。外観とキーボード設定は VS Code の機能を使用します。

変更は保存時に送信します。モデル照会は候補を返すだけで、自動保存しません。
リセットは継承値を復元します。競合時は下書きを保持し、ランタイム変更時は消去します。
外部の attach-only ランタイムは閲覧専用です。

この画面の提供者キーは DSH の資格情報サービスで保存します。既定のローカル保存先は
`$DSH_HOME/.credentials.yaml` で、POSIX では所有者のみがアクセスできます。提供者の
profile および既存の SecretStorage キーとは別の保存先です。暗号化保管庫ではなく、
同じ OS ユーザーで動くツールからの隔離も提供しません。保存済みの値は画面に返さず、
資格情報ファイルは Git と VSIX に含めません。

### 自律デバッグ

VS Code の設定で **DeepSeek Harness: Autonomous Debugging** を有効にし、`.vscode/launch.json` にデバッグ構成を追加します。

DeepSeek はサイドバーからデバッガーを起動し、ブレークポイントの設定、ステップ実行、実行時の値の確認、コードの修正、結果の検証まで行えるようになります。

基本的な会話・設定インターフェースは DeepSeek Harness `0.2.1-rc.2` でも隔離環境で確認済みです。従来の検証対象は `0.2.0-rc.2`、`0.1.7-rc.1`、`0.1.7-rc.2` です。0.1.9 では外部タスク、Search / Fetch 設定、推論マッピング、ユーザーメッセージの資格情報マスクに対応しました。Workdir／Worktree の統合は個別検証が必要です。任意のサービスは実際のランタイムバージョンとプロファイルに依存します。

## プライバシーと検証

送信済みユーザーメッセージは公式ルールで認識できる資格情報を隠し、個別に表示できます。表示上の制御であり、モデルへの送信、履歴、助手・ツールの出力、明示的なコピー内容は変更しません。未認識の秘密情報は表示される場合があります。

鍵ボタンで設定した API キーは VS Code SecretStorage に保存します。保存したランタイム起動 URL は所有者のみがアクセスできるローカルファイルに保存し、同期しません。ファイル参照は明示的に追加します。プロンプトと選択したコンテキストは、設定したモデルサービスへ送信される場合があります。

[0.1.5 のレビュー](docs/RELEASE-REVIEW-2026-10-15.md) は修正、プライバシー確認、テスト範囲、検証上の制限を記録します。開発時の `braces` にはバージョンに基づく警告が残ります。ローカルの深さ制限パッチは報告済みの再帰問題に対応し、この依存関係とパッチは VSIX に含めません。

不具合や機能の提案は [GitHub Issues](https://github.com/fallleaves01/dsh-vscode/issues) に報告してください。
