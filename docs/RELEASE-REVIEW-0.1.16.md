# 0.1.16：共享连接状态与重试复核

日期：2026-10-23。用户报告服务器安装 0.1.15，连接后显示 Starting，几十秒后可以进入对话。
本次只检查和修改本地插件，没有连接服务器，没有读取服务器会话或进程记录，没有安装、推送或发布。

## 结论与修复范围

不能仅凭此现象认定共享实例未被复用。0.1.15 已有自动发现、身份核验与连接既有实例的流程。
本地代码确认的缺陷是：复用实例后建立事件订阅和读取历史时，界面可能保留先前的启动文案，
没有显示连接来源；状态指示错误匹配 `starting`，而控制器实际使用 `loading`。

尤其在远程扩展主机仍存活、Webview 重新创建时，控制器先将界面重置为 Starting，而已处于
ready 的 runtime.start() 直接返回缓存连接，不会再次发布运行时启动事件。旧界面随后等待
事件订阅及历史读取时便一直保留 Starting。此次为这些读取阶段增加独立状态与累计时间记录。

另有两个可复现问题：关闭 `autoStart` 时初始界面仍显示正在启动；首次连接失败后 Reconnect
要求本窗口已有 ready 运行时，因此不能重试连接其他窗口留下的健康实例。已补充回归用例并修复。

- 顶部显示 Shared、DSH 或 External，分别对应连接既有受管实例、本窗口启动实例、外部实例。
  工具提示提供已知 PID；点击重新连接本窗口。只有连接类型和 PID 进入 Webview，没有传递 URL 或凭据。
- 明确区分共享操作等待、登记检查、启动检查、配置准备、版本检查、凭据加载、已有实例连接、
  事件订阅和历史加载。加载时提供 Show Output；输出记录阶段及累计连接耗时。
- 自动启动关闭时显示待连接状态和 Connect。手动 Retry Connection 重新执行发现和认证，
  不要求先终止已有健康实例。自动事件流重连仍不会发起新的运行时启动。
  显式外部连接认证失败时继续要求其启动 URL，不因重试而切换为受管实例。
- 启动中的跨窗口操作锁等待和既有启动等待使用 `startupTimeout`。此前操作锁固定默认等待
  310 秒；新的默认单阶段等待为 60 秒。超时保留原操作与运行时，不强行接管锁。
  此设置不是整个初始化流程的总时限，也不能中断同步文件系统调用。
- 更新恢复按钮时包含 canReconnect，修复状态文本不变时按钮未更新的问题。

这些修改提高状态准确性与诊断能力，不代表已经定位或消除了用户服务器上的具体延迟。
远程文件系统耗时、事件订阅耗时和历史加载耗时仍需该服务器的输出日志才能区分。
