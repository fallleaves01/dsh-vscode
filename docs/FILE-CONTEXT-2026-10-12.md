# 主动选择文件上下文（0.1.2，2026-10-12）

后续代码及安全检查的修正发布为 `0.1.3`，见 [发布前复核记录](RELEASE-REVIEW-2026-10-12.md)。

用户希望能主动添加、删除文件，并取消编辑器当前文件的强制加入。
此前发送快照确实会自动包含当前文件引用和选区正文；本轮同时修改界面和发送快照。

## 使用方式

- 输入框底部的 `+` 打开文件菜单。输入路径或文件名搜索，可连续添加多个项目文件或目录。
  当前编辑文件和选区会作为标注 optional 的快捷候选，默认不选中。
- 选择后显示紧凑标签，点击文件名打开文件，点击 `×` 移除。菜单内再次点击已选项也能移除。
  关闭菜单后可继续输入；`Esc` 或 Done 返回输入框，图片附件入口保留在菜单底部。
- 打开文件、切换编辑器、改变选区都不会自动添加引用或复制选区正文。
  手动 `@file`／`@folder`、拖入资源、**Add Selection to Chat** 和 **Fix with DeepSeek** 仍是明确的添加操作。
- 引用按会话保存草稿。发送成功后消费本次发送的引用；发送失败保留草稿。
  发送期间后来添加的引用、其他会话的引用不会被成功回执清掉。

这里的引用列表控制插件随消息提供的文件上下文。模型仍可根据用户请求和工具权限读取项目中的其他文件。
草稿保存范围是当前扩展运行期间，尚未新增跨 Reload Window 的文件引用持久化。

## 实现与验证

- 编辑器状态只提供候选元数据；普通消息没有 `@` 时不扫描项目，也不读取选区正文。
- 查询和添加／删除带会话标识；过期搜索结果不覆盖新查询或新会话。
  路径在扩展宿主解析并限制在当前项目内，并发添加完成后再次去重。
- 添加／删除得到宿主回执前，发送按钮和 Enter 都等待，避免界面刚点完却发送旧引用。
  清理发送引用时匹配原会话和原快照，保留之后新增的文件。
- `npm run check`：90 个测试文件、1124 项测试通过，1 项 Windows 原生 cmd 测试在 macOS 跳过；
  类型检查和生产构建通过。新增用例覆盖自动注入取消、移除后不恢复、并发添加、切换会话、
  快照清理、过期搜索、发送等待和图片入口。
- `npm run test:scroll-browser`：17 组真实 Chromium 检查通过。
  文件菜单在 320×400、420×800、650×800 下没有横向溢出，搜索和底部操作可见，发送按钮可见。
  验证了原生键盘添加、等待回执、多文件标签、删除、当前编辑文件仍未选中和 Escape 返回输入框。
  保留既有滚动、三主题、模型菜单、子任务和独立详情回归。
