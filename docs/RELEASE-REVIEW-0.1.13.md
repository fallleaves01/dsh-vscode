# 0.1.13：共享运行时重启恢复复核

日期：2026-10-22。仅修改本地插件，未连接用户服务器、安装远程扩展或推送代码。

## 已确认的问题

配置指纹不匹配时，启动会在取得运行时连接和使用者记录前失败。原有 Restart Runtime
只清理当前窗口已经取得的连接、进程和使用者记录，因此无法停止导致此次失败的已登记
共享实例。下一次启动仍检查同一个实例并再次失败。原来的错误消息还罗列了全部候选
字段，不能指出实际不一致的字段。

另一个本地回归用例复现了空项目目录的重复创建路径：创建出的空会话没有出现在后续
列表时，`loadSessions` 递归查询目录并再次创建会话。此循环没有次数上限。该用例曾使
测试进程耗尽堆内存；这不能证明用户服务器发生过同样的问题。

## 修复后的行为

- Restart Runtime 能从启动失败状态处理已登记的受管实例，并用当前窗口配置重新启动。
- 其他窗口仍在使用时，原生确认框列出受影响窗口数量，说明运行中对话、子代理及
  定时任务会中断。取消时保留现有连接；其他窗口需使用一致配置并重新加载。
- 确认只覆盖当时的实例和使用者。停止前再次核验实例、进程、启动身份和认证地址；
  实例已更换或有新窗口接入时，保留现状并要求重新检查。
- 操作系统启动身份可证明进程归属时，HTTP 服务无响应也可执行手动恢复。否则使用
  原实例的启动令牌验证；身份仍不能证明时拒绝发送信号。
- 先发送 SIGTERM 并等待退出；必要时再次验证身份后发送 SIGKILL。旧进程无法确认退出时，
  保留记录并报告失败，不启动替代进程。外部、仅连接的运行时不进入此停止路径。
- 配置错误只输出实际不一致的字段名称，不输出参数、环境变量值或凭据。
- 项目切换只断开和重新连接当前窗口，不触发全局共享重启确认。
- 空项目创建会话后，直接打开返回的会话 ID。打开失败也不重复创建；替代实例启动或
  会话打开失败时，重启操作不再报告成功。
