# 0.1.14：共享运行时生命周期与异常清理复核

日期：2026-10-23。仅修改本地插件及测试、文档。未连接或修改用户服务器，未修改 DSH
安装文件、用户配置或 VS Code 设置，未推送、发布或安装扩展。

## 行为与实现

- 保留一个辅助进程托管同一主机、账号、DSH home 下的共享实例。创建窗口关闭后，
  其他有效使用者继续连接同一个 DSH，历史搜索和 Schedule 保留。
- Linux Remote–SSH 的使用记录和操作锁记录对应 VS Code Server 的 PID 与启动身份。
  最多读取八级直接祖先进程的 `/proc` 信息，未使用全进程表或文件系统扫描。
  Server 身份无法验证时拒绝启动受管实例；Server 已退出的残留扩展主机不能继续保留使用权或操作锁。
- 远程连接意外中断时，DSH 随原生远程扩展主机继续存活。插件不复制或覆盖
  `remote.SSH.reconnectionGraceTime`。该设置不保证正常关闭全部窗口后继续运行。
- 无有效使用者时，每 5 秒检查，经过 30 秒宽限期清理。辅助进程的启动握手等待上限为
  15 秒；DSH 未报告 URL 时另有启动超时保护。停止先发送 SIGTERM，4 秒后必要时发送
  SIGKILL。后代进程持有输出管道不再导致辅助进程无限等待。
- POSIX 平台为 DSH 创建独立进程组，只向该已知进程组发送清理信号。PID 被复用时
  不向新进程组发送信号。主动脱离该进程组的外部工具不属于此保证。
- 辅助进程退出不再等同于 DSH 已退出。创建窗口或其他存活使用窗口可以检测辅助进程
  异常死亡，验证 DSH 身份并清理，随后显示失败状态；不自动重启。
- Linux 僵尸进程不再视为存活使用者。旧辅助进程不能删除同一窗口更新后的启动记录；
  停止旧 DSH 不能删除替代实例的登记记录。输出 IPC 排队大小受到限制。
- 托管协议更新为 `ipc-2`。所有使用窗口需更新，并明确执行 Restart Runtime 替换旧辅助
  进程；仅重新连接不会升级已在运行的旧辅助程序。

## 验证

类型检查和生产构建通过。完整测试：108 个文件，1,416 项通过，1 项既有跳过。
第一次受限沙箱执行中，回环端口及一个既有 HOME 临时文件用例被环境拒绝；在获准的
本地测试环境重跑后通过。未使用远程环境规避限制。

隔离 HOME 的真实进程故障注入覆盖：IPC 断开但仍有使用者、最后使用者释放、拒绝
SIGTERM、DSH 事件循环阻塞、后代持有管道、辅助进程被强制终止、URL 发布前辅助进程
退出、启动取消、Server 退出但扩展主机仍在，以及启动前 IPC 丢失。

真实官方 DSH 多进程测试确认：并发启动一个实例、不同 VS Code 配置目录、同一会话的
多客户端连接、创建窗口退出、重新连接、扩展主机崩溃、共享重启、历史搜索与 Schedule。
新增用例确认创建窗口已关闭时，两名剩余使用者都能识别辅助进程被杀死，并进入失败状态。
没有发送模型请求。真实 Chromium 的聊天界面 26 组及设置页 8 组检查通过。

本地真实进程测试运行于 macOS。Linux `/proc` 识别、僵尸进程和 Server 身份策略通过
注入平台数据的单元测试验证；未在用户的真实双窗口 Remote–SSH 环境中执行验收。

## 隐私与限制

新增持久化内容仅为进程 PID 与启动身份，不保存 Server 命令行、环境变量或配置文件
内容。认证 URL 仍位于用户私有登记文件，不传入 Webview、不写入日志。新增测试使用
合成凭据及临时目录。没有新增第三方依赖；既有开发依赖 braces 的版本告警及本地修补状态
没有改变。本次不声称全部依赖告警已消失。

清理时间依赖操作系统调度。辅助进程与全部扩展主机同时被 SIGKILL 时，无存活代码执行
清理；SIGSTOP、内核不可中断 I/O、信号被拒绝、身份或使用记录不可读，也可能阻止
及时清理。此时保留不确定记录，避免启动竞争实例；由手动重启或遗留实例恢复执行身份核验。
持久历史可在重启后打开，运行中的模型请求和工具调用不能原地恢复。
