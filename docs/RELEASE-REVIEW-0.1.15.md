# 0.1.15：下一次连接前的遗留运行时恢复

日期：2026-10-23。仅修改本地插件、测试和文档。没有连接或修改服务器，没有修改 DSH
安装文件、用户配置或 VS Code 设置，没有推送、发布或安装扩展。

## 行为

- 共享受管运行时的启动流程取得跨窗口操作锁后、连接认证和会话打开之前，检查辅助进程
  与 DSH 的 PID 和启动身份。辅助进程存活且配置兼容时继续使用既有重连流程。
- 辅助进程已确认退出且没有其他有效使用窗口时，核验并停止残留 DSH。旧实例退出后才
  创建新的受管实例。多个窗口同时连接时串行执行恢复，避免同时启动多个 DSH。
- 新辅助进程在连接地址发布前，将 DSH 启动身份与托管协议写入私有启动登记文件。
  管理进程在此阶段全部退出时，下一次连接仍可核验和清理。记录不含连接地址或凭据。
- PID 被复用时不向新进程发送信号。缺少身份、记录不一致、信号被拒绝或有其他有效使用者
  时保留记录并报错，不启动竞争实例。外部、仅连接的运行时不进入清理路径。
- 保持 `ipc-2` 协议及既有正常退出、断线宽限和共享重启机制；没有后台自动重启循环。
  升级后需要在合适时机执行 Restart Runtime，才能让新的辅助进程写入启动身份。

## 验证

- 类型检查与生产构建通过。完整单元测试 109 个文件，1,432 项通过，1 项既有跳过。
  其中新增 16 项覆盖遗留实例恢复、PID 复用、身份缺失、外部实例、使用者冲突、取消、
  信号拒绝、未知协议和启动登记不一致。
- 隔离 HOME 的真实官方 DSH 多进程测试通过 22 项行为检查，包含全部管理进程被强制
  终止后的并发恢复、已保存会话重新打开、历史搜索与 Schedule。故障前暂停 DSH，验证
  SIGTERM 无法处理时可升级到 SIGKILL，替代实例就绪前旧进程已退出。
- 独立故障注入通过 11 项行为检查，新增 URL 发布前扩展主机与辅助进程同时被强制终止，
  随后由下一次启动核验并清理残留进程。测试只操作自身创建的进程，没有发送模型请求。
- 本次首次历史恢复测试暴露了测试前提问题：DSH 对新建会话的事件采用约 200 毫秒缓冲，
  立即强制终止时日志可能尚未创建。测试现先确认合成会话日志已存在，并按插件真实流程
  重新打开会话后读取命令；不以任意固定等待时间代替落盘检查。
- 真实进程测试运行于本地 macOS；Linux 身份和 Server 生命周期逻辑由既有单元测试覆盖。
  没有在用户的 Remote–SSH 环境执行验收。本次没有修改 Webview，未重复上一版浏览器测试。

## 隐私与边界

新增持久化字段仅为启动身份和托管协议，沿用私有目录及 0600 文件权限。错误消息不包含
认证 URL、环境变量或凭据；不会扫描全进程表或读取用户会话内容用于恢复判断。没有新增依赖，
既有开发依赖 braces 的版本告警及本地修补状态未改变。

管理进程全部退出后，到下一次插件运行之前，仍没有代码执行清理。辅助进程被停止但未退出、
内核不可中断 I/O、权限拒绝、不可读的身份或使用记录，也可能阻止恢复。若在启动身份写入前
发生强制终止，不能安全自动终止该未知进程。主动脱离 DSH 专用进程组的工具不在清理保证内。

恢复只保留已经写入日志的会话历史；内存中的未写入事件、运行中的模型请求和工具调用不能
原地恢复。此版本不修改 DSH 的持久化机制或缓冲策略。

`artifacts/ui-review/runtime-recovery-next-start/`。
